Named uncertainty

Operator path

The file becomes two accountable sets

  1. Validate every row without creating customers.
  2. Commit the valid set and assign stable import-row receipts.
  3. Download the invalid set with row-level reasons, correct it, and retry.
  1. Validation keeps each source row’s identity before any customer is created.
  2. Valid rows commit once and receive receipts that make later retries harmless.
  3. Invalid rows return with reasons; a corrected retry references only those open receipts.
Outcome-protecting rules

Every row ends in a knowable state

  • A row is either committed or rejected; no customer is half-created.
  • Every committed row has a stable receipt before the result is shown.
  • Retry accepts corrected rejected rows and ignores already committed receipts.
  • Every rejection names a field and a correction reason.

Correction belongs to the operator

The system may normalize harmless formatting, but it never invents missing identity or consent data.

Observable proof

The count survives retries

  • The first run reports 788 committed and 12 rejected, with 800 row receipts.
  • Retrying 12 corrected rows creates at most 12 customers and leaves the first 788 unchanged.
  • The final summary accounts for every source row and links each rejection to its reason.
