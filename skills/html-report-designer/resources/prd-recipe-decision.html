Send a receipt only after the order is real

Resolve the product promise behind a deceptively small timing choice.

  1. Moment. A buyer submits an order and sees a confirmation message.
  2. Friction. The receipt can arrive before the order survives a save failure, creating false confidence and support work.
  3. Bet. Confirm submission immediately, but send the receipt only after durable save.
  4. Proof. No buyer receives a receipt for an order the system cannot recover.
  5. Boundary. This does not redefine payment capture or fulfillment timing.

The product promise

“Receipt sent” means the order has crossed the durability boundary, not merely that the browser submitted it.

Review focus

Is a short delay preferable to a fast but occasionally false receipt?

Canonical journey

One promise, three visible moments

The buyer always knows whether the order is being saved, saved, or needs attention.

  1. Submit. The page acknowledges the request and shows “Saving order…”
  2. Save. Durable storage succeeds; the page shows the order number.
  3. Receipt. The system sends the receipt and the page confirms delivery or offers a resend.
Promise-protecting rules

The receipt follows evidence

  • Never send a receipt before durable save succeeds.
  • If save fails, show recovery copy and send no receipt.
  • If receipt delivery fails after save, keep the order and offer resend.
  • Resending does not create another order.

In this bet

  • Order confirmation copy, receipt timing, and resend behavior.

Outside this bet

  • Payment authorization and fulfillment policy.
Product decision

Choose durable save before receipt

The message becomes trustworthy and support can reason from it.

Tradeoff
Buyers may wait a few seconds longer during slow saves.
Rejected
Sending immediately and retracting later; the first message has already created the wrong belief.

Channel choice stays open

Email is the first delivery channel. SMS or push receipts need separate evidence and consent decisions.

Observable proof

Trust is visible in failure

  • A saved order shows its number before receipt confirmation appears.
  • A forced save failure produces recovery copy and no outbound receipt.
  • A forced delivery failure preserves the order and exposes resend.
