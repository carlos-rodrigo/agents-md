Pressure

Independent templates drifted in shell, styles, and runtime

Causal path

Structured truth becomes one self-contained report

  1. Author
    The owning skill writes canonical-report-v1 structured content.
  2. Generate figure
    System Diagram renders retained system-diagram-v1 JSON into accessible infrastructure SVG.
  3. Render
    The canonical renderer validates roles, decisions, and provenance before filling one report template.
  4. Review
    The reviewer records and exports choices without mutating canonical source.
System path

One boundary coordinates report generation

  1. The owning skill supplies validated product or architecture content.
  2. System Diagram supplies the retained system-diagram-v1 JSON/SVG pair.
  3. The canonical renderer validates both inputs.
  4. One report template produces portable HTML for review.

Tradeoffs and proof

Stricter structure buys determinism and review safety

Cost
New component shapes require a shared renderer change.
Failure posture
Missing renderer or System Diagram provenance blocks generation rather than falling back.
Proof
Clean-copy, negative profile, deterministic regeneration, decision runtime, and browser checks pass.
Migration risk

Legacy generated reports remain readable but are not accepted as new canonical output.

Meaningful boundary

The renderer does not decide product or architecture truth

  • No automatic approval from completeness or browser state.
  • No alternate diagram renderer or hand-authored SVG.
  • No task creation or implementation behavior inside design generation.
