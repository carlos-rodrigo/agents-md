Approved Feature design Updated 2026-07-31

Put all document presentation behind one portable renderer

PRD and Design Solution own structured meaning, System Diagram owns Excalidraw JSON-to-SVG, and HTML Report Designer validates both before filling one report template.

Review first

Verify the renderer seam, strict failure behavior, decision lifecycle, and package-relative installation path.

Explicit human approval

Approved by Carlos Rodrigo on 2026-07-31.

Approved authority

One report experience must preserve domain-owned truth

Product promise
Every durable report uses one dependable shell, decision lifecycle, and Excalidraw figure contract.
Authority source
Editable approved product truth comes from prd.document.json; prd.html is its current validated review projection.
Acceptance
Single production template, deterministic rendering, complete decision export, Excalidraw provenance, and browser resilience.
Constraint
Presentation must not invent, reorder, or approve product/architecture content.
Architecture pressure

CWD-relative templates and parallel render paths made drift inevitable

The obvious approach—telling agents to copy the right template—cannot guarantee consistent output.

Ownership pressure
PRD/design skills mixed content policy with shell placeholders and CSS mechanics.
Portability pressure
Installed skills could not resolve repository-root scripts and assets from unrelated projects.
Consistency pressure
Separate template/CSS/runtime families evolved independently.
Trust pressure
Browser selections lacked an explicit canonical approval boundary.
Chosen seam

HTML Report Designer owns the sole rendering boundary

PRD
Owns required product roles, slices, acceptance, and product decision lifecycle.
Design Solution
Owns required architecture roles, seam, path, proof, and ADR consequences.
System Diagram
Owns evidence validation and bundled Excalidraw JSON-to-SVG generation.
HTML Report Designer
Owns schema validation, block rendering, report template, CSS, navigation, review runtime, and report validation.
Human approver
Owns transition from Draft/Review/Proposed to Approved/Accepted.
No fallback path

A missing companion skill, invalid profile, absent Excalidraw provenance, or incomplete approval blocks generation instead of producing a substitute artifact.

Causal path

Validated meaning crosses one rendering seam

  1. Compose
    PRD or Design Solution writes canonical-report-v1 JSON with required section roles, stable IDs, approval state, and decisions.
  2. Generate
    System Diagram validates a bounded question and renders retained Excalidraw JSON into accessible SVG.
  3. Validate
    The canonical renderer rejects unknown fields, missing roles, incomplete slices, invalid decisions, and non-Excalidraw figures.
  4. Render
    The renderer fills the sole report template and embeds shared CSS, navigation, decision runtime, DocumentSpec, and template digest.
  5. Review
    The human reads self-contained HTML and exports review decisions; an agent reconciles only explicitly accepted truth.
Architecture path

The renderer seam sees content, figure provenance, and output together

  1. PRD or Design Solution supplies required structured meaning.
  2. The DocumentSpec makes approval, decisions, roles, and IDs machine-checkable.
  3. System Diagram supplies retained Excalidraw JSON and generated SVG.
  4. HTML Report Designer validates both and fills one report template.
  5. Invalid authority or provenance blocks; valid input emits deterministic portable HTML.

Tradeoffs and proof

Strict failure is cheaper than silent drift

Cost
A new semantic component requires a shared schema/renderer change and focused tests.
Benefit
All document kinds receive the same fixes, styles, controls, and fallbacks.
Failure posture
Invalid roles, approval, decisions, source paths, or provenance fail before output.
Recovery
Correct structured source or install the declared companion skill; never patch output.
Proof strategy
Positive/negative profile fixtures, template lock, decision runtime test, copied-skill rendering, deterministic checks, Excalidraw freshness, and desktop/mobile/no-JS/reduced-motion/print browser checks.
Legacy artifacts

Existing reports remain readable, but new validation rejects them as canonical generation sources until migrated.

Meaningful boundary

The renderer remains intentionally ignorant of domain decisions

  • No automatic product or architecture choice from available components.
  • No implied approval from completeness, browser persistence, passing tests, or prior implementation.
  • No alternate report template, CSS family, diagram renderer, or hand-authored SVG path.
  • No task creation, implementation steps, or execution evidence in PRD/design generation.
  • No external Pi configuration gate inside this repository's default verification command.

The architecture ADR owns the durable single-renderer rationale; this feature design owns the current paths, profiles, and verification consequences.
